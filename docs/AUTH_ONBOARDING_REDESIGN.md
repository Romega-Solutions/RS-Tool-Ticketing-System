## Audit Summary

### What Was Found

| Severity | Finding | Resolution |
|----------|---------|------------|
| **Note** | `proxy.ts` IS the Next.js 16 middleware — no `middleware.ts` needed | Confirmed working; deleted conflicting duplicate |
| **High** | Login + onboarding used manual `useState` form state (no validation schema) | Replaced with `react-hook-form` + `zod` |
| **High** | No animations on any auth surface | Added full animation set (see below) |
| **High** | No progress indicator on onboarding | Added 3-step progress bar |
| **High** | Error messages showed but had no motion — easy to miss | Errors now shake into view |
| **Medium** | Demo account block always visible — credential exposure in prod | ENV-gated via `NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS` |
| **Medium** | Password toggle had no `aria-label` | Added `aria-label="Show/Hide password"` |
| **Medium** | Tab switch (Sign In ↔ Create Account) was instant/jarring | Slide-in animation on each switch |
| **Medium** | Department pills had no selection feedback | Bounce animation on select |
| **Low** | Signup success used `📬` emoji as icon | Replaced with `<MailCheck>` Lucide icon |

## Design System (UI/UX Pro Max Output)

- **Style:** Flat Design — 2D, minimal, no heavy shadows, WCAG AAA
- **Colours:** RS brand palette kept — primary blue `--rs-primary-500`, accent orange; no indigo introduced
- **Font:** Merriweather (headings) + Source Sans 3 (body) — matches RS brand, not replaced
- **Animations:** 150–300ms ease; `transform`/`opacity` only — no `width`/`height` transitions
- **Anti-patterns avoided:** Complex multi-screen wizard, cluttered layout, layout-shifting hover states

## Animation Inventory

All keyframes are wrapped in `@media (prefers-reduced-motion: no-preference)` — zero motion for users who prefer it.

| Class | Keyframe | Duration | Where Used |
|-------|---------|----------|------------|
| `animate-auth-enter` | fade + slide up 12px | 300ms ease-out | Page wrapper on both auth pages |
| `animate-tab-enter` | fade + slide right 6px | 150ms ease-out | Tab panel on each tab switch (`key={tab}`) |
| `animate-shake` | left-right shake | 300ms ease-in-out | Error message div (new `key` per error rerenders it) |
| `animate-pill-select` | scale bounce 0.93→1.05→1 | 200ms ease-out | Department pill on select |
| `animate-card-select` | box-shadow pulse ring | 350ms ease-out | Role card on select |
| `animate-slide-up` | existing — fade + up 6px | 200ms ease-out | Field-level zod error messages |
| `animate-pulse` (Tailwind) | opacity pulse | continuous | Skeleton placeholder while domain detects |

## Form Architecture

### Login (`src/app/login/page.tsx`)

- Two `useForm` instances — `signInForm` and `signUpForm` — one per tab
- Zod schemas enforce: email format, password min-length, name min-length
- Field-level errors appear inline below each input with `animate-slide-up`
- Server errors appear at the top of the form with `animate-shake`
- `errorKey` increments on every new server error → remounts error div → retriggers shake
- `key={tab}` on the panel div → remounts on tab switch → triggers `animate-tab-enter`
- Password eye toggle has `aria-label` for screen reader accessibility
- Demo block hidden unless `NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS=true` in env

### Onboarding (`src/app/onboarding/page.tsx`)

- Single `useForm` with zod — name (min 2), role (enum), team (min 1), jobTitle (optional)
- `useEffect` calls `supabase.auth.getUser()` → detects `@romega-solutions.com` domain
- While detecting: skeleton placeholder renders (`h-[72px] animate-pulse`) → no layout flash
- Non-romega emails: role locked to `ic`, shows locked card with `<Lock>` icon
- Progress bar: watches `name` and `team` fields → advances step 1→2→3 reactively
- Department pills use `setValue('team', ..., { shouldValidate: true })` → errors clear on select
- Submit button flashes green (`bg-green-500`) on success, then redirects after 700ms

## Environment Variable

| Variable | Value | Effect |
|----------|-------|--------|
| `NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS` | `true` | Shows demo account buttons on sign-in tab |
| *(not set)* | — | Demo block hidden — safe for production |

Add to `.env` for local dev:
```bash
NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS=true
```
Do **not** add to Vercel production environment variables.
