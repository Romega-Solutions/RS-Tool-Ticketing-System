# RS Ticketing System — Migration Plan

How to move from the current markdown/Excel workflow to the ticketing system.

## What Gets Migrated

| Source | Destination | Method |
|--------|-------------|--------|
| `MASTER-TODO.md` task items | Tasks in the ticketing system | Script (one-time import) |
| `C1/TODO-RomegaDigital.md` tasks | Tasks under project C1 | Script |
| `C2/TODO-PinayMate.md` tasks | Tasks under project C2 | Script |
| `C3/TODO-InternalTools.md` tasks | Tasks under project C3 (with stream tags) | Script |
| `C4/TODO-Upskilling.md` tasks | Tasks under project C4 | Script |
| Excel weekly report template | Weekly report generator (built-in) | Structural mapping |
| Excel attendance sheet | Attendance tracking (built-in) | Structural mapping |
| Blocker table in MASTER-TODO.md | Blocker-flagged tasks | Script |
| Team roster | User accounts (7 core members seeded) | Seed script |

**What does NOT migrate:** Historical weekly reports from the Excel file. Those stay in Excel as archives. The new system starts fresh — the first reports generated by the system are for the current week at launch.

## Migration Script

A one-time script parses the markdown TODO files and creates task records.

### Parsing Rules

**Checkbox status:**
- `[ ]` (unchecked) → task status `todo`
- `[x]` (checked) → task status `done`, with `completed_at` = file last-modified date

**Priority emojis:**
- 🔴 → `high`
- 🟡 → `medium`
- 🟢 → `low`
- No emoji → `medium` (default)

**Assignee tags:**
- `@Ken` → assignee = ken
- `@Mark` → assignee = mark
- `@Robbie` → assignee = robbie
- `@Cherry Ann` → assignee = cherry_ann
- `@Mich` → assignee = mich
- Multiple `@` tags → first one is assignee (mention others in description)
- Unassigned → assignee = null

**C3 Streams → Tags:**
- Tasks under "Stream A" heading → tag `stream-a`
- Tasks under "Stream B" heading → tag `stream-b`
- Through "Stream G" heading → tag `stream-g`

**Blocker table:**
Each row in the "Blocked / Waiting On" table creates or updates a task with:
- `is_blocker = true`
- `blocker_description` = the "Blocks" column text
- Matched to existing task by title similarity, or created as new task if no match

### Example Parsing

**Input (from MASTER-TODO.md):**
```markdown
- [ ] 🔴 Codebase migration: Vanilla JS → NextJS — @Ken
```

**Output (task record):**
```
title: "Codebase migration: Vanilla JS → NextJS"
project: C1
assignee: ken
priority: high
status: todo
```

**Input (completed task):**
```markdown
- [x] Extract images and take screenshots
```

**Output:**
```
title: "Extract images and take screenshots"
project: C1
status: done
completed_at: (file last-modified date)
priority: medium
```

## Migration Phases

### Phase A: Seed Data (Before Launch)

1. **Create user accounts** for 7 core team members with temporary passwords
   - Admin force-resets passwords on first login
   - Each user gets: username, temp password, name, email, role, team

2. **Create projects:** C1, C2, C3, C4 with descriptions and leads from MASTER-TODO.md

3. **Create default tags:** design, dev, urgent, waiting-approval, stream-a through stream-g

### Phase B: Import Tasks (Before Launch)

1. Run migration script on all 5 TODO files
2. Verify imported tasks:
   - Correct project assignments
   - Priority mapping matches emoji
   - Assignees matched to user accounts
   - Blocker flags set on correct tasks
   - C3 stream tags applied
3. Manual review: Mark (PM) walks through imported tasks and fixes any mismatches

### Phase C: Parallel Operation (2 Weeks)

Run the new tool **alongside** the existing workflow:

**Week 1:**
- Team enters tasks in the ticketing system AND continues Trello/markdown
- Weekly reports generated from the ticketing system BUT also filled in Excel as backup
- Focus: Get comfortable with the tool. Identify missing features, confusing UX, wrong data.

**Week 2:**
- Team primarily uses the ticketing system
- Excel report is generated FROM the ticketing system (via export), not manually filled
- Compare exported report with manually-created Excel report to verify format match
- Fix any gaps or formatting issues

### Phase D: Cutover

After 2 weeks of parallel operation with no critical issues:

1. **Archive markdown TODOs:**
   Add a header to each TODO file:
   ```markdown
   > ⚠️ ARCHIVED — Tasks have moved to the RS Ticketing System.
   > This file is kept for historical reference only.
   ```

2. **Stop Excel weekly reports:**
   IC reports come exclusively from the ticketing system. The exported .xlsx replaces the manually-filled workbook.

3. **Update MASTER-TODO.md:**
   Replace the detailed task lists with a link to the ticketing system:
   ```markdown
   ## Task Management
   All tasks are now tracked in the RS Ticketing System at [URL].
   This file is kept as a high-level project index only.
   ```

4. **Trello continues as-is:**
   Departments that use Trello can keep using it. The ticketing system is now the source of truth for reporting. Trello integration (bidirectional sync) is a Phase 3 feature.

### Phase E: Workspace Integration

1. Add project entry to `Work - Romega Projects (Workspace)/CLAUDE.md`:
   ```markdown
   | `RS_Tool-Ticketing-System` | Plane.so (Docker) + Python report script | (VPS) | — |
   ```

2. Update root `CLAUDE.md` and `README.md` with the new project (note: Plane.so is self-hosted on VPS, not a local dev project)

3. Mark C3 tasks as resolved:
   - A.2 "Trello automation: clicked task → moved to weekly report" → Done
   - A.3 "N8n/Zapier integration: Trello → Google Sheets" → Done
   - A.4 "Trello x Weekly Report — find alternative" → Done
   - F.5 "Cross-department visibility for Tech ICs" → Done

## Rollback Plan

If the ticketing system fails or team adoption is low:

1. The markdown TODO files are archived, not deleted — they can be restored
2. The Excel template is still available — just resume filling it
3. All data in the ticketing system can be exported to Excel at any point
4. No irreversible changes are made during migration — everything is additive
